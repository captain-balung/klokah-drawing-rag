## A. 總則區

### 專案精神

我們要讓瀕危的原住民族語繪本「**容易被找到、被讀懂**」，而不是讓它們繼續沉睡在一個需要逐本點開、逐族切換的網站裡。

我們追求**忠實呈現族語資料的原貌**，不是追求「看起來很厲害的 AI」。具體而言：當族語內容與華語翻譯有差異時（例如某族對某食物有更精確的描述），我們保留差異而非抹平；當 Claude 不確定某繪本內容時，寧可說「資料庫沒有」也不憑空生成。

> 這條精神可被引用拒絕方案，例如：「讓 LLM 自由發揮補充繪本沒有的族語例句」違反本精神——我們不製造看似族語、實則捏造的內容。

### 總體規範

1. **資料忠實優先於回答流暢**：Claude 的所有繪本事實必須來自資料庫；寧可回答不知道，不可捏造族語內容或繪本資訊。違反判準：回應中出現資料庫不存在的繪本 ID、書名或族語文字。
2. **成本可見且受控**：每次 LLM 呼叫必須啟用 prompt caching；任何會顯著增加 token 用量的設計變更，須在 `log.md` 記錄預估成本影響。違反判準：system prompt 未設 `cache_control`，或新增功能未評估 token 成本即合併。
3. **機器優先**：可自動化且可逆的操作（起 dev server、跑測試、查 log、build、前端視覺驗證），AI 自行用 CLI/MCP 完成並驗證，不丟回人類手工。違反判準：把可用 `curl`/Playwright 自動驗證的事丟回人類目視檢查。
4. **不為功能犧牲隱私與授權**：使用者查詢內容不外傳第三方（Claude API 除外，那是核心依賴）；繪本資料的使用不得違反原平臺授權。違反判準：把使用者查詢送到分析/廣告/第三方記錄服務。
5. **可讀性優先於聰明**：寧可多寫三行清楚的程式，不寫一行需要註解才看懂的炫技。違反判準：為節省行數而犧牲後人理解的程式碼。

## B. 產品定義區

### 核心命題

一個對話式查詢服務：把「族語 E 樂園」95 本繪本的內容載入 Claude 的上下文，讓使用者用中文自然語言找書、讀內容、問問題。

### 目標使用者

少數人內部使用——族語教學的同事、相關科系學生、研究團隊。技術背景不一（從完全不懂程式到工程師都有），因此前端要直覺到「打開網頁就會用」。使用情境：備課找教材、研究時檢索特定族語表達、好奇某主題有哪些繪本。

### 範圍邊界

**做什麼：**

- 提供自然語言查詢繪本的對話 API 與完整前端網頁
- 支援多輪對話（記得前文）
- 支援查看繪本完整內容、特定族語版本、逐頁文字
- 提供繪本資料的抓取（爬蟲）與格式轉換工具
- **對外提供 MCP server**：讓其他聊天機器人/AI 助手以 Model Context Protocol（Streamable HTTP）查詢繪本資料

**明確不做什麼（擋住 scope creep）：**

- ❌ **不做使用者帳號/登入系統**——內部少數人用，不需要
- ❌ **不做對話歷史持久化**——後端 stateless，對話由前端保存
- ❌ **不做 vector 資料庫/embedding/chunking**——資料量小，整包進 context 即可
- ❌ **不做繪本內容的編輯/新增/管理後台**——原始資料只讀
- ❌ **不做族語語音合成或翻譯生成**——只呈現平臺既有內容
- ❌ **不做即時爬取**——爬蟲是離線批次工具，不在查詢時觸發
- ❌ **不做多語介面（i18n）**——介面只有繁體中文

### 成功標準（可驗收）

1. 使用者輸入「推薦關於 X 主題的繪本」，系統能在 20 秒內回傳至少一本資料庫中真實存在、主題相關的繪本（含 ID、書名、級別）。
2. 使用者要求「給我第 N 本的 Y 族語版本第 Z 頁」，系統回傳的族語文字與 `books/book_N.json` 中該族該頁的 `text` 完全一致。
3. 連續兩輪對話中，第二輪問題引用第一輪結果（如「其中哪一本最適合幼兒？」），系統能正確理解指涉對象。

## C. 功能與資安區

### 工程紅線

1. **不准把 API 金鑰寫死在程式碼或進版本控制**——一律用環境變數；`.env` 必須在 `.gitignore`。
2. **不准 catch 後吞例外**——錯誤要嘛處理、要嘛往上拋並留 log，不准 `except: pass`。
3. **不准修改原始繪本資料**——`data-pipeline/output/` 與 `data-pipeline/output_v2/` 的繪本 JSON 對後端是唯讀，任何寫入都是違規。
4. **不准在日誌印出完整 API 金鑰或使用者完整查詢內容**——log 只記必要的營運資訊。
5. **不准在查詢路徑做即時網路爬取**——爬蟲與查詢嚴格分離。

### 功能清單

| ID | 簡述 | 驗收條件（可機器驗證） |
|---|---|---|
| F-01 | 自然語言找書 | POST `/api/chat` 傳入主題查詢，回應 `text` 含至少一個存在於 `index.json` 的書本 ID |
| F-02 | 繪本內容問答 | Claude 呼叫 `fetch_book_detail` 工具後，回應中的族語文字與對應 `book_*.json` 一致 |
| F-03 | 多輪對話 | 傳入含前輪 assistant 訊息的 messages，第二輪回應正確指涉第一輪結果（人工抽驗 + 回歸測試固定案例）|
| F-04 | 繪本瀏覽 API | GET `/api/books` 回傳 95 筆；GET `/api/books/{id}` 回傳對應書本完整 JSON，404 處理正確 |
| F-05 | 繪本抓取（爬蟲）| `scraper.py all` 對既有書本斷點續爬，產生的 `book_*.json` 通過 schema 驗證 |
| F-06 | 格式轉換 | `transformer.py` 產生 `index.json`、`summary.jsonl`、去重後 `books/*.json`，中文差異記入 `chinese_variants` |
| F-07 | SSE streaming 回應 | POST `/api/chat/stream` 回傳 `text/event-stream`，事件含 text/tool_use/done |
| F-08 | 健康檢查 | GET `/api/health` 回傳 `books_loaded` 等於實際載入數 |
| F-09 | 對外 MCP server | `/mcp` 通過 MCP Streamable HTTP 協定（initialize → tools/list → tools/call）；提供 `list_books`/`search_books`/`get_book`/`get_book_page` 四項純資料工具；**不暴露任何呼叫 Claude API 的能力**；對外完全公開（無 token），以 per-IP rate limit 防爬 |

### 反例規格（不該做什麼）

- 找書功能**不該**回傳資料庫中不存在的繪本（捏造 ID 或書名）
- 內容問答**不該**改寫或「優化」族語原文，必須原樣呈現
- 多輪對話**不該**在後端儲存任何使用者對話內容
- 爬蟲**不該**在使用者查詢時被觸發
- 日誌**不該**記錄完整 API 金鑰或可識別使用者的完整查詢
- API 回應**不該**洩漏伺服器檔案路徑、堆疊追蹤給前端使用者
- **對外 MCP server 不該**暴露任何會呼叫付費 LLM API 的工具——chat 留在 `/api/chat` 給前端，**絕不上 MCP**（否則外部使用者每次查詢都燒我們的 Anthropic 額度，違反成本鐵則）
- **對外 MCP server 不該**提供寫入/修改/刪除類工具——純讀繪本靜態 JSON

### 資料與資安要點

1. **處理什麼資料**：(a) 95 本繪本的公開內容（中文 + 16 族語文字 + 音檔/圖片 URL）；(b) 使用者即時輸入的查詢文字；(c) Claude API 金鑰。
2. **資料敏感度**：繪本內容為公開資料但受 CC 授權約束；使用者查詢屬低敏感但不應外流；**API 金鑰為高敏感**，外洩等於財務風險。
3. **AI 不可接觸什麼資產**：AI agent 不可讀取或輸出 `.env` 內的金鑰值、不可把金鑰寫進任何受版控檔案、不可將使用者查詢送往 Anthropic 以外的第三方服務。
